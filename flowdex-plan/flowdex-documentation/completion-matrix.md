# Flowdex completion matrix

This matrix maps the product contract to its supported entry point, user documentation, and focused evidence. It is an audit guide, not a runtime manifest.

| Capability | User-facing entry point | Source of truth | Focused evidence | Intentional limit |
| --- | --- | --- | --- | --- |
| Save and run native JavaScript workflows | `save_flowdex_workflow`, `start_flowdex_workflow` | [Groundwork](groundwork.md) | `codex-core` Flowdex integration suite; `codex-flowdex` loader tests | Native V8 only; Node is not required or exposed. |
| Reusable agents, profiles, tool overlays, and direct messaging | Workflow `agents`; agent spawn/resume/message APIs | [Agent workflows](agents.md) | `codex-core` Flowdex agent, profile, signal, and status-only tests | Tool profiles only restrict tools; they do not replace agent profiles or encode roles. |
| Runs, phases, dependency scheduling, dynamic queues, and sealing | `flowdex.startRun`, `queueTask`, `sealPhase`, `awaitRun` | [Executable workflows](workflows.md) | Joined Flowdex scenario; `codex-flowdex` workflow validation tests | Scope conflicts are advisory scheduling constraints, not filesystem enforcement. |
| Task worktrees, commit attribution, and deterministic integration | Task `read_scope`/`write_scope`; scheduler-managed task completion | [Task worktrees](task-worktrees.md) | Joined Flowdex scenario; `codex-flowdex` store lifecycle and attribution tests | Live-process recovery only; no process-restart resurrection. |
| Silent command verification and repair | Task, phase, and run `verification` | [Silent verification](verification.md) | Joined Flowdex scenario; focused command verification tests | Verification repair and review have separate limits. |
| Structured review, attribution, and resolution | Task/phase `review`; review findings APIs | [Review findings](reviews.md) | Joined Flowdex scenario; focused review attribution and resolution tests | Arbitrary low-level review calls do not gain scheduler attribution automatically. |
| Context packs and context reuse | Run `context_packs`; task `context`; `publishContextFragment`; keep/compact/handoff | [Context packs](context-packs.md), [Context compaction](compaction.md) | Joined Flowdex scenario; focused context collection, injection, and reuse tests | Packs are injected only into dependent tasks; collection does not block unrelated ready work. |
| Event-driven waits, steering, signals, and boundaries | `await_tasks`, workflow wait APIs, named signals, `continue_phase` | [Event-driven waits](waiting.md), [Executable workflows](workflows.md) | Joined Flowdex scenario; focused steering, signal, and boundary tests | Waiting is live and event-driven; it does not promise process-restart recovery. |
| App-visible children with isolated completion | Normal app-server agent lifecycle events; StatusOnly workflow ownership | [Agent workflows](agents.md) | Joined Flowdex scenario; focused app-server lifecycle and StatusOnly tests | Completion stays out of orchestrator context without hiding child lifecycle events. |
| Automatic progress summaries | Scheduler transitions and live reasoning-summary events | [Progress summaries](progress.md) | Joined Flowdex scenario; focused progress/history isolation tests | Progress is not callable, persisted, returned, or replayed into later model input. |
| Reusable and nested workflows | `invokeWorkflow` with explicit `repo:` or `global:` reference | [Reusable workflows](reusable-workflows.md) | Focused strict input/output, identity, cancellation, cycle, and wait tests | Repository workflows never silently shadow global workflows. |
| AST-grep verification and candidate promotion | Approved repository rules; direct-model candidate scan and rule editing | [AST-grep rules](ast-grep-rules.md), [Review findings](reviews.md) | `codex-flowdex` AST-grep, history bound, configuration, and candidate tests | Candidate scanning is bounded and read-only; rule changes require explicit human approval. |
| Configuration, installation, and compaction reminder | Global/trusted-repository Flowdex config; `codex flowdex install --binary`; `compact_context` | [Desktop app installer](windows-app-installer.md), [Context compaction](compaction.md) | Focused Windows/macOS injected installer tests; Flowdex config and core compaction tests | Installer support is Windows/macOS; a live macOS host run is not claimed here. |

The joined scenario intentionally leaves timing-sensitive steering races, compaction internals, generic research loops, nested-cycle cases, installer platform mutation, rule-history bounds, and exhaustive schema rejection to their focused owning tests.
